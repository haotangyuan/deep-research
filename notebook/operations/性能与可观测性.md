# 性能与可观测性

## 性能策略

1. Supervisor Leader 根据预算生成有限数量的原生 Task，AgentScope Research Team 使用 `asyncio.gather` 按 `maxConcurrentUnits` 并发执行隔离 Worker。
2. Tavily 查询使用规范化参数作为缓存 key，TTL 缓存避免重复搜索，in-flight 合并避免并发重复请求。
3. 网页摘要按 URL 与内容缓存，并限制摘要并发数、输入字符数和单次超时；失败时降级使用 Tavily 原始摘要。
4. 报告阶段通过 `RESEARCH_REPORT_FINDINGS_MAX_CHARS` 限制汇总材料，避免最终模型调用因上下文膨胀出现长尾延迟。
5. 后台任务使用有界队列和固定 worker，队列满时快速拒绝，避免无界内存增长。
6. 每个网页摘要使用独立 AgentState，避免并发网页互相继承上下文；SearchAgent 状态不进入 checkpoint，防止 Redis 快照复制网页正文。
7. 长生命周期 Agent 使用 AgentScope `ContextConfig` 自动压缩，同时继续保留网页、研究材料和报告输入的硬上限。

预算默认值：

| 预算 | 子研究 | 每个子研究搜索 | 并发数 | 单次结果 |
|---|---:|---:|---:|---:|
| MEDIUM | 2 | 2 | 1 | 3 |
| HIGH | 4 | 3 | 2 | 3 |
| ULTRA | 6 | 4 | 3 | 3 |

## 可观测链路

OpenTelemetry span 层级：

```text
deep_research.workflow
  -> deep_research.stage <AgentName>
    -> AgentScope invoke_agent <AgentName>
      -> AgentScope chat <ModelName>
      -> AgentScope execute_tool <ToolName>
```

公共属性包括 `research.id`、`user.id`、`model.id`、`budget.level`、`workflow.status`、token 用量和调用延迟。Langfuse 使用 OTLP HTTP 导出；也可配置任意兼容接收端。

FastAPI 生命周期首先初始化一个全局 OpenTelemetry SDK `TracerProvider`。项目的 `workflow/stage/tool/model` span 和 AgentScope 2.0.3 `TracingMiddleware` 读取同一个 Provider，因此原生 AgentScope span 会自然成为当前 workflow/stage 的子节点，而不是形成第二条孤立链路。

默认不记录提示词和模型输出。启用 I/O 采集后，系统会按字符上限截断，并对 Authorization、API key、secret 和 token 脱敏。

ULTRA 动态工作流额外补充了业务可观测性：

- 动态决策节点：展示 `strategy / nextAction / qualityScoreboard / weak sections / next focus`
- 动态任务批次节点：展示每轮任务拆解结果
- 干预节点：展示用户追加的下一轮偏置及其采纳结果
- 报告前验证节点：展示是否存在证据缺口以及最终披露要求

## 验证

- `pytest` 验证 AgentState 隔离、TaskContext、Middleware 预算、团队并发、快照和事件元数据。
- `api_feature_smoke.py` 验证认证、模型 CRUD、研究创建、归档和删除。
- `live_hybrid_workflow_smoke.py` 使用数据库中的 Mimo 配置验证 HITL、AgentScope Team、搜索、报告、Token 和持久化。
- `PYTHONPATH=. conda run -n deep-research-py python tests/observability_smoke.py` 验证共享 Provider、父子 Trace ID，并真实导出四层无敏感测试 Span；成功输出 `export=SUCCESS`。
- Langfuse 中可按 `service.name=deep-research` 或 `research.id` 查找业务研究链路；smoke trace 使用 `service.name=deep-research-observability-smoke`。
